# Changelog

## 0.1.1-beta

- Added installation-time timezone confirmation. The release installer reports the validated system timezone before activation, lets a directly attached administrator keep it or choose a listed IANA timezone, supports the noninteractive `SLS_MASS_NOTIFY_TIMEZONE` override, and restores the original timezone if a later installation stage rolls back.
- Refined update and Danger Zone progress into compact accessible status cards with clear operation names, success/failure states, and a subtle reduced-motion-aware progress indicator. Manual and automatic update paths retain verified release metadata, exact SHA-256 enforcement, explicit automatic-update opt-in, and visible terminal results.
- Added up to 10 optional named Discord or Discord-compatible HTTPS Dashboard announcement webhooks under General Settings. Each enabled destination can be selected independently from the Dashboard, including as the only destination, and receives a bounded branded Discord embed JSON payload. The protected URLs are never returned to the page or logs; local phone, audio, and desktop submission runs before bounded external delivery so a slow webhook cannot delay an urgent local announcement.
- Added per-zone Weather Alert controls for quiet hours, email recipients, desktop clients, Discord webhooks, and generic HTTPS webhooks. Zone routing stays isolated so one alert is sent only to the destinations assigned to its matching area.
- Added per-area Lightning controls for strike type, quiet hours, phones, desktops, email recipients, and all-clear behavior across as many as five trigger areas. Shared Discord and generic webhook definitions remain protected in General Settings.
- Expanded adaptive Lightning protection with time-aligned Weather.gov forecast gating. A future thunder period is recorded but does not spend Xweather tokens before its start; the forecast cache expires at the period boundary so polling can begin on the first scheduler run at or after that time. Current qualifying alerts remain authoritative, and protected grace and quota controls still apply.
- Removed the Labs designation from Lightning Alerts and Lightning trigger areas while retaining the module-wide beta notice. Consolidated the Dashboard announcement composer into two responsive sections with compact destination disclosures, bounded lists, counts, improved Packery relayout, and accessible in-progress/result states. AJAX widget refreshes now dispose prior timers, observers, listeners, and delayed layouts instead of accumulating background work. Weather and Lightning tests use the same polished operation-status presentation.
- Serialized Weather Alert delivery through one bounded audio queue so simultaneous NWS alerts do not overlap phone pages. Each alert's SIP visual step follows its audio start, and queue faults are reported through module health.
- Added lock-protected cross-zone delivery claims and deterministic zone turns. Overlapping Weather groups no longer submit the same alert chain twice to a shared phone, desktop, email address, Discord webhook, or generic webhook; unique destinations remain scoped to their configured zones. Coordination state stores only domain-separated destination hashes and is bounded and pruned.
- Fixed manual Weather tests falsely reporting that Asterisk had not picked up a page while the active call file was still present in the outgoing spool. The worker now recognizes the active `Local/<extension>@sls-alert-audio` channel, publishes the selected desktop event independently before phone work, attempts every requested local channel, and reports partial failures without replaying successful submissions.
- Fixed protected-config validation for the canonical per-zone `quiet_critical_events` field, preventing a valid Weather zone policy from being mislabeled as an overbroad central configuration. Live Weather and Lightning groups may now use an email or enabled webhook as their only delivery route; manual tests remain local-only and require a phone or enabled desktop target.
- Removed the avoidable handset delay from live desktop delivery. Weather and Lightning write the targeted desktop journal first, then retain the two-second page-first delay only for phone SIP NOTIFY. A sleeping or disconnected desktop remains a successful durable publication rather than a delivery fault.
- Clarified desktop presence and delivery status. Connected, recently disconnected, and sleeping clients are distinguished without treating a sleeping computer as a live session; queued records remain subject to client targeting and expiry when the app reconnects.
- Improved cross-PBX SIP NOTIFY routing. Mixed phone families on one extension receive contact-specific vendor payloads when URI routing is available and a safe generic endpoint payload otherwise. An unknown phone format alone no longer blocks installation, and SIP/SIPS contact URIs retain UDP, TCP, TLS, ports, parameters, and IPv6 syntax.
- Reduced Discord branding to a compact thumbnail and stable public HTTPS image assets, with payload-size and field-limit validation.
- Standardized every Discord and Discord-compatible announcement card on the SLS Mass Notification System display name and Southland Servers logo profile image. The same stable HTTPS logo is also used for compact author/footer branding, while the card artwork remains a thumbnail rather than a large inline image.
- Replaced the Notification Logs severity column with a backward-compatible notification-type taxonomy. Existing JSONL records are classified at display time as Dashboard, Control API, Scheduling, Weather, Lightning, manual test, desktop, system/error, or other events; historic filter URLs remain compatible and full Weather severity remains available in event details.
- Expanded Dashboard health for Weather, Lightning, scheduling, desktop streaming, external destinations, protected configuration, runtime parity, audio queue state, and installer/repair failures.
- Hardened installation and repair around FreePBX/Asterisk variations, runtime ownership, module hooks, local signing, AMI discovery, provider checks, and post-install parity. Validation remains conservative and does not rewrite phone firmware, SIP peers, or unrelated FreePBX configuration.
- Fixed the full Danger Zone repair path after `fwconsole chown`: the scheduled-announcement PHP worker remains executable, the protected post-repair verifier completes, and the central configuration remains byte-identical. Signer and verifier children now close their inherited maintenance-lock descriptor so a background FreePBX GPG key refresh cannot leave later repair, update, or uninstall work falsely blocked.

## 0.1.0

- Fixed a fresh-install backup-health false fault. FreePBX Backup is now an explicit adaptive installer prerequisite, the release verifier confirms the native adapter is discoverable and enrolled in every existing module-based job, and a PBX with no administrator-defined backup jobs is correctly reported as ready instead of misconfigured. The installer does not invent a schedule, storage destination, or retention policy.
- Added up to five named Lightning trigger areas. Each area independently selects its Weather.gov adaptive trigger group, Xweather location/radius, phone extensions, enabled desktop clients, email recipients, and all-clear behavior while retaining shared credentials, cadence, quiet hours, tones, voice, and volume. Manual Lightning tests can exercise selected applied areas, and legacy single-area configuration migrates without losing its existing phone or all-desktop routing.
- Isolated Lightning storm/clear state and delivery correlation per area while enforcing one shared protected Xweather quota governor. Multiple storm-active trigger zones can issue separate area queries during the same cycle. The Lightning page keeps a concise multi-area token notice without a speculative planning calculator.
- Fixed stale Xweather account-period presentation and quota recovery. Provider usage headers are recorded as one timestamped snapshot, expired reset periods are clearly labeled historical instead of current, an old exhausted balance cannot deadlock the new period, and a successful storm query or **Verify Applied Areas** refreshes the counters. The usage page now uses compact current/historical token and progress cards instead of a dense paragraph.
- Added simple Weather.gov zone lookup instructions to the Weather Alerts editor, setup wizard, Help, README, and installation guide. One official NWS zone-map link now explains how to choose a state, find the three-digit zone number, and combine it with the state abbreviation and `Z` (for example, `TXZ163`).
- Extended each Weather Alert zone group with explicit desktop-client and email recipients. Live alerts are routed only to that zone's selected phone, desktop, and email targets, while manual tests continue to suppress email and webhooks.
- Corrected false manual Weather-test failures caused by treating an archived Asterisk call-file status as proof of handset delivery. Tests now require bounded outgoing-spool pickup plus the requested SIP and/or desktop submission paths, report those results honestly as queued/submitted, and no longer fail solely because a Local/Page origin is later archived as `Expired`.
- Reworked **Email and Webhook Delivery** so General Settings owns the local Postfix sender identity, optional system/error email recipients, multiple Discord webhooks, and multiple generic HTTPS webhooks. Weather and Lightning live-alert email recipients now belong to their individual zone or trigger area. Pre-0.1.0 global email lists migrate into existing service routes instead of being silently dropped; system/error mail remains opt-in.
- Added a deduplicated system/error email notifier to the one-minute maintenance worker. Active Weather, Lightning, scheduling, installation, update, and maintenance faults are submitted once through the branded local Postfix path, clear when health recovers, and can notify again if the condition later returns. Multi-area Lightning uses per-area poll and delivery state without duplicating its mirrored aggregate fault; successful Weather fault mail is acknowledged in zone and Dashboard status. Mailer failures use a bounded retry interval.
- Kept legacy email migration fail-closed across raw runtime reads, config imports, FreePBX restore, and Control API updates. Old `mail_to` values move only into Weather/Lightning live routes; an empty service route cannot fall back to system/error recipients, and the obsolete Control API field returns explicit migration guidance instead of silently changing meaning.
- Added one shared live-alert dispatcher for Weather and Lightning. Email is submitted through the local sendmail path, Discord receives the branded compact card, and generic webhooks receive bounded structured JSON with an event ID and idempotency header. Webhook validation requires HTTPS, resolves only public addresses, pins the validated address for TLS, blocks redirects, limits payloads/retries, and keeps credentials out of results and logs.
- Fixed Discord branding that could appear as an invalid webhook avatar or embed image. Discord payloads now use stable public Southland Servers HTTPS PNG assets for the profile image and card image instead of a PBX-hosted URL that may be private, unreachable through Discord's proxy, or stale behind a query-string cache key.
- Kept manual Weather and Lightning tests local. Tests can exercise the phone, audio, desktop, status, and popup paths without sending email, Discord, or generic webhook traffic.
- Changed direct audio fan-out to Asterisk `Page()`/ConfBridge. Every resolved PJSIP contact can join the page, preventing a softphone registration from displacing a desk phone on the same extension. The generated call-file origin remains alive for the measured WAV plus a two-second teardown margin, while a five-second participant window avoids holding promptly answered phones in silence after playback.
- Made Dashboard announcement feedback visible beside **Send Announcement**. The widget shows preparation, final success/warning, and partial-channel failures; if the browser loses the response, Send remains disabled until the cooldown probe confirms whether a retry is safe.
- Published selected desktop announcements before synchronous TTS and phone work, or immediately after audio-duration discovery when the display timeout follows the page. Phone submission is isolated with `--no-api`, desktop publication is explicitly targeted with `--api-only`, and mixed phone/desktop paths cannot write the same journal event twice.
- Removed repeated filesystem repair and AMI discovery from read-only page rendering. Request-local, file-fingerprint-guarded caches now cover normalized settings and endpoint inventories, and atomic settings writes invalidate those caches centrally. This keeps configuration concurrency checks intact while substantially reducing Dashboard and Mass Notify page render time.
- Fixed request-time runtime protection around Piper. The root-owned compatibility virtual environment is now treated as a strict, non-writable trust boundary instead of being traversed by the Asterisk account, preventing otherwise valid announcements from failing before delivery while preserving fail-closed ownership checks.
- Normalized the legacy single-area Lightning identifier to `lightning_primary`, migrated legacy state safely, and retained unprefixed legacy correlation keys so applied-area verification, manual testing, all-clear state, and retry history remain continuous after upgrade.
- Made the audio dialplan initialize its FreePBX device/AOR fallback before the secondary contact lookup. Community Asterisk builds no longer expand `PJSIP_DIAL_CONTACTS()` with a blank argument while normal extension-first fan-out remains unchanged.
- Changed Yealink auto-answer to the documented `Alert-Info: Intercom` value and added installer guidance for handset-side **Intercom Allow**. Visual XML still requires **Features > Remote Control > SIP Notify** or `push_xml.sip_notify = 1`; installation never changes phone provisioning, firmware, or peer definitions.
- Tightened mixed-registration checks and installer preflight for `Page`, ConfBridge, PJSIP contact resolution, persisted module providers, AMI discovery, sound paths, and runtime/package parity across standard and community FreePBX systems. Installation hard-fails for mixed phone formats when complete contact URIs and a usable default outbound endpoint are unavailable.
- Corrected delivery wording throughout the runtime. A successful AMI action or call-file write now reports the request as queued or submitted to Asterisk, not delivered to a handset. Phone acceptance, auto-answer, rendering, and SIP responses remain device-side results.
- Added protected install/repair failure state. FreePBX Dashboard health shows a red fault with the failed stage and a suggested next action; the fault clears only after comprehensive integration, signature, runtime, and health verification succeeds.
- Fixed the scheduled-announcement health false positive. Missing worker/cron/journal checks become actionable faults only when at least one schedule is enabled, so merely opening Scheduling no longer creates a fault on an otherwise unused installation.
- Added repeat choices to Scheduling for every 7 or 14 days at the selected PBX-local time. Recurring occurrences are generated as a protected DST-validated series for up to five years, remain bounded by the existing 366-occurrence limit, and retain the same recipients, audio, voice, tones, and color options as one-time schedules.
- Added native FreePBX 17 backup and restore adapters for protected configuration, the schedule execution journal, and custom module tones. Restore verifies the manifest, hashes, sizes, configuration structure, credentials, and WAV data before atomic activation, prevents due/completed schedule replay, and performs post-restore integration verification.
- Added best-effort enrollment in existing module-based FreePBX backup jobs and Dashboard reporting when enrollment is absent. FreePBX cannot automatically fetch this custom module on a replacement PBX, so `slsmassnotifyserver` must be installed before restoring its module data; an independent `.config` backup remains recommended.
- Retained the established `SLS_Mass_Notifications_Plugin` filesystem paths for upgrade compatibility while using **Module** in current user-facing names and documentation.

## 0.0.9-beta

- Added a dedicated **Scheduling** tab for up to 100 saved one-time announcements and 366 calendar occurrences per schedule. Each schedule can target configured phones, announcement groups, desktop clients, all phones, or all desktops and can retain text-only, tones, Piper TTS voice/volume, and Labs color presentation choices.
- Added a one-minute Asterisk-account scheduling worker with a 15-minute missed-run window, a single-worker lock, persistent occurrence claims, bounded retries before delivery begins, and fail-closed handling for an unreadable execution ledger. Temporary cooldown, busy, and offline-target conditions retry without bypassing global announcement protections; a delivery that may already have begun is marked uncertain and never replayed automatically.
- Added DST-safe PBX-local calendar validation. Nonexistent spring-forward times and ambiguous fall-back times are rejected, UTC instants are normalized strictly, editor values follow the current operating-system timezone, and Dashboard health warns when FreePBX's configured PHP timezone disagrees with the operating system.
- Added schedule health checks for missing recipients, removed groups/desktops, unavailable tones or Piper voices, audio without a phone target, stale worker status, duplicate/misconfigured cron entries, and enabled schedules without a current or future occurrence.
- Made schedule changes revision-checked and coordinated with the protected active/pending settings lock so a simultaneous General Settings save or Apply Config cannot silently overwrite a schedule. Configuration imports and FreePBX restores retain schedule definitions but disable them for administrator review because the PBX-local execution ledger is deliberately not portable.
- Closed the remaining Control API/setup apply race by validating and removing staged settings inside the same configuration lock as the active write. A concurrent authenticated UI/import save now causes a retryable revision error instead of being silently deleted.
- Added **Announcement Timeout** under General Settings. Regular announcements default to no expiry and can instead use the remaining generated audio duration or a fixed 1–86,400 seconds. Yealink XML receives the normalized timeout and live desktop records receive display timeout/UTC expiry metadata; expired desktop events are filtered from new delivery while retained history remains available for audit. Other phone families remain firmware-dependent, and Weather Alert validity is unchanged.
- Added **Email Sender Domain** to the General Settings Notification Destinations manager. Fresh installs derive the domain from the detected PBX hostname, the module fixes the complete sender to `no-reply@<domain>`, and strict DNS-hostname validation rejects schemes, addresses, IP literals, invalid labels, and header-control characters. Existing configs without `mail_from_domain` inherit the domain from a valid legacy `mail_from_addr`; the canonical value is portable with the protected central config and allowlisted for validated Control API updates.
- Documented the email boundary in the UI and manuals: changing the sender domain does not configure Postfix, an SMTP relay, SPF, DKIM, DMARC, PTR/reverse DNS, or other DNS records.
- Fixed live desktop stream cursor handling for expiring announcements. An expired event can advance the authenticated client cursor without being emitted, and the next valid targeted event is no longer skipped.
- Fixed a Weather.gov chain-identity edge case that could suppress a genuinely new first-issued alert when the feed included historical references. Only `Update` messages inherit the oldest referenced chain identifier; subsequent time-only edits remain deduplicated. Heat Advisory is present in both the runtime map and FreePBX event choices.
- Isolated manual Lightning test status from live Lightning delivery health. An Asterisk `Expired` test call now names the affected extension and explains that the page was not answered within the test window instead of exposing a random call-file name or leaving live delivery in a fault state. Upgrade repair migrates the narrowly matched legacy `sls_xweather_*.call: Expired` status out of global/live health and into manual-test history.
- Isolated manual Weather test failures from live alert health and external destinations. Failed tests remain visible in the FreePBX popup, local status, and Notification Logs, but cannot send a fault email or Discord webhook; upgrade repair narrowly migrates the old manual-test fault records out of live health. Alert-worker `--help` and unknown arguments now exit before locks, API calls, audio, SIP NOTIFY, or desktop delivery can begin.
- Hardened cross-PBX audio paging. The pre-dial handler keeps the outgoing PJSIP contact as its first User-Agent source, passes the target extension explicitly, and falls back through the FreePBX device/AOR mapping when a community Asterisk build does not populate that channel field.
- Expanded adaptive installer prerequisites to cover the exact PHP CLI path, OpenSSL, mbstring, POSIX, Python/venv/pip, SoX, ImageMagick, fonts, download/archive tools, cron/locking utilities, `PJSIP_AOR`, `CUT`, and every Asterisk function/application used by the paging contexts. Missing Debian packages are installed selectively; a complete system skips the package-index refresh. Effective dial-string components must resolve to real PJSIP endpoint objects, so a fabricated `PJSIP/<extension>` fallback no longer passes validation.
- Added pre-activation validation for preserved AMI credentials and FreePBX's actual local AMI host/port. Existing central configuration is never paired with a transient generated AMI secret; malformed credentials, an invalid port, or a non-loopback Manager host stop safely before activation without printing or changing protected values.
- Verifies that every required Asterisk provider will still load after restart. Systems using `autoload=no` must explicitly load each provider, while a matching `noload` entry is rejected with the affected module name instead of passing a temporary runtime-only check.
- Added ownership-safe bundled System Recordings with unique `SLS_Mass_Notify_*` names. Existing unrelated recordings and a non-SLS `/usr/local/bin/piper` wrapper are never overwritten; uninstall removes a bundled recording only while its row, metadata, and audio hash still prove module ownership.
- Canonicalized the scheduling cron to exactly one protected entry, added Asterisk-account worker self-tests, preserved the PBX-local schedule execution ledger during a normal uninstall, and extended install/repair/uninstall parity and release regressions for all new runtime files.
- Strengthened release packaging so credentials, private keys, logs, caches, backups, model files, nested archives, signatures, and generated artifacts fail the build instead of entering the TGZ.
- Renamed user-facing **Plugin** wording to **Module** throughout FreePBX and Dashboard presentation. Established `SLS_Mass_Notifications_Plugin` data, sound, and asset paths remain unchanged for update compatibility.

## 0.0.8-beta

- Fixed false missing-capability failures on downstream/community Asterisk builds that print `Info about function` or `Info about application` with different capitalization. The installer now matches the complete quoted capability heading case-insensitively while preserving the exact requested name, so an already registered function does not incorrectly enter provider loading or Debian package repair.
- Reworked PBX-local signing to use the configured FreePBX web account, web root, spool directory, and exact GPG home instead of hardcoded `asterisk` paths. Existing keyring ownership is repaired before import, GPG operations are bounded and retried, and only the documented `{"status":129,"details":[]}` result is accepted.
- Serialized key generation and module signing with a dedicated lock. Candidate signatures are published transactionally and retained only after verification, a failed verification restores the previous `module.sig`, and concurrent first-run signing no longer creates competing local keys.
- Coordinated installer, updater, repair, maintenance drift recovery, and complete uninstall through the maintenance lock. Maintenance-launched children reuse the inherited lock; direct CLI work waits instead of racing the minute worker.
- Deferred module-hook signing during managed install and repair transactions so the final stable module, Dashboard, and Framework trees are signed once after FreePBX reload.
- Hardened complete uninstall by snapshotting the current transactional signer before the module hook removes its normal copies. Repository-offline cleanup can sign and verify the cleaned Dashboard and Framework trees with that protected copy, which is removed before exit; older installations retain the compatibility path.
- Added release regressions for wrong-owned FreePBX keyrings, concurrent first-run signing, signature rollback, signer replacement, inherited maintenance locks, and uninstaller signer snapshots.
- Fixed installation on FreePBX systems where an Asterisk paging provider is unloaded, missing, or damaged. Before downloading or activating the module, the installer checks every dialplan function and application used by direct paging, dynamically loads the matching provider, and verifies the capability instead of trusting the Asterisk CLI exit code. If a dpkg-owned provider such as `res_pjsip_header_funcs.so` still cannot register, the installer pins the repair to the exact already-installed owning package version, prohibits package removal, and retries. Package repair is deferred during active calls. An unavailable exact version or unowned/custom Asterisk build fails safely before the existing module or protected configuration is changed rather than mixing incompatible ABIs.
- Fixed the Lightning Alerts AJAX test failure that appeared as “failed before delivery could be confirmed.” The page was calling a private cooldown-status method after the worker completed; the method is now part of the public module API, JSON responses tolerate invalid UTF-8 safely, and unexpected server errors return a sanitized failure instead of a broken response.
- Fixed cross-PBX SIP NOTIFY portability. Same-format registrations now use endpoint-targeted `PJSIPNotify`, allowing Asterisk to preserve the endpoint's transport, NAT, authentication, and full contact fan-out without requiring a PBX-specific default outbound endpoint.
- Corrected AMI contact parsing to use Asterisk's documented `Uri` field case-insensitively and to prefer `Endpoint` over fallback object names. AMI responses now count only explicit `Response: Success`; blank, permission, and unrelated errors fail delivery.
- Made mixed-vendor registrations safe. Per-contact URI routing is used only when every registration has a distinct usable URI and Asterisk has a real default outbound endpoint. Missing URI support now returns a clear error, and a failed per-contact send is never retried by broadcasting that vendor's XML to every phone on the extension.
- Fixed empty AMI inventory suppressing Dashboard targets. The Dashboard falls back to the Asterisk CLI when AMI returns no numeric endpoints, while the release installer requires registered numeric CLI contacts to appear in AMI with a detected format and contact count.
- Corrected first-run public-link detection without trusting ordinary Host-header GET requests. The authenticated setup submission records the browser PBX hostname when the installer could see only a local placeholder and updates the generated `no-reply` address only while it is still untouched.
- Expanded fresh-install prerequisites and verification across FreePBX Framework, Dashboard, and System Recordings; PHP OpenSSL; Apache modules/configuration; cron; Asterisk WAV support; AMI `PJSIPNotify`; exact runtime/API/asset parity; System Recordings rows; public image rendering/fetching; an authenticated desktop live-SSE handshake; conditional authenticated Control API status; fresh safe defaults; and real Amy, Lessac, and Ryan synthesis. Missing required FreePBX modules are installed and disabled dependencies are enabled without silently upgrading an installed core module.
- Made required Piper voice failures fatal and pinned all six model/metadata files to their published hashes. The installer no longer reports success after a failed voice download.
- Fixed failed-install rollback ordering so the active module's uninstall hook removes partial AMI, dialplan, Apache, cron, Dashboard, API, runtime, bundled System Recording, and persisted Dashboard-hook integration before the old module is restored. Normal Module Admin uninstall now removes executable runtime and web/API routes while preserving the protected central configuration and persistent user data.
- Added strict copy failures and stale managed-file pruning for runtime, APIs, and public assets. Release builds now run cross-PBX SIP routing regressions, require the two uninstaller copies to be byte-identical, and accept only the documented exact local-signature result `{"status":129,"details":[]}`.
- Fixed the release installer on PBXs with no registered PJSIP contacts. Asterisk 22 can return AMI `Response: Error` with the exact message `No Contacts found` even when the `slsmassnotify` login and `PJSIPShowContacts` authorization are valid. The health check now treats only that narrowly matched empty-inventory response as authorized, returns `{}` for endpoint listing, and continues to reject authentication, permission, transport, and unrelated AMI errors.
- Strengthened installer health-result validation and the standalone/packaged uninstaller. The installer now parses and verifies its AMI health JSON instead of trusting only the process exit code. The uninstaller requires root plus a working FreePBX/database bootstrap before changing state, and an EXIT guard restores preserved central configuration, backups, and uploaded tones if a normal non-purge uninstall stops early. Release building now syntax-checks the PHP programs embedded inside both uninstaller copies.
- Fixed Weather Alerts silently dropping Heat Advisories. `Heat Advisory` is now a supported Weather.gov event, and the one-time upgrade migration removes only stale Heat Advisory chain records that 0.0.7 incorrectly marked processed while the event was unsupported.
- Removed the event-name-wide six-hour suppression of Weather.gov `Update` messages. A first-seen alert chain is now eligible for delivery even when NWS labels it as an update; reference-based chain keys still suppress timestamp-only reissues after that chain has actually been processed.
- Strengthened Weather and Lightning system tests. Tests run synchronously, require Asterisk to archive every targeted test call as `Completed`, require SIP NOTIFY submission to succeed, and return sanitized delivery errors to the FreePBX page. The pages show a visible error popup for registration, audio, payload, AMI, timeout, and related failures.
- Stopped Weather and Lightning tests from sending email or Discord notifications. Test results remain in Notification Logs and status data, while live Weather and Lightning events continue using the shared configured destinations.
- Prevented Weather dry-run fixture failures from using the live fault-email route. Dry-run faults remain visible in the selected local status/log files without contacting external destinations.
- Added per-contact SIP NOTIFY capability discovery. Same-format registrations use portable endpoint fan-out; mixed phone formats use direct contact URIs only when every contact is addressable and Asterisk has a usable default outbound endpoint. Long TLS contact URIs are no longer taken from Asterisk's truncated contact table.
- Added `Heat Advisory` to the visual alert map and retained urgency-aware branded presentation for phone and desktop delivery.
- Updated Sangoma audio paging to use Sangoma's documented `Alert-Info: intercom` auto-answer value for P- and S-series devices. Sangoma visual SIP NOTIFY remains provisioning-, model-, and firmware-dependent and should be verified on the target handset.
- Fixed a Discord live-alert failure caused by non-ISO timestamps. The branded sender now normalizes valid timestamps to UTC and safely substitutes the current UTC time when the caller supplies a human-readable date.
- Made Weather and Lightning call-file delivery atomic by staging call files in Asterisk's spool filesystem before moving them into `outgoing`. Test-result archives use the protected `outgoing_done` directory and are removed immediately after validation.
- Added live Danger Zone status for Repair Installation and Complete Uninstall, including queued, running, completed, and failed states. Configuration replacement now shows upload/validation progress and a completion result without exposing protected config values.
- Added a recoverable adaptive release installer. It validates FreePBX, Asterisk, required modules, disk space, spool ownership, every staged PHP/Bash/Python file, AMI authorization, dashboard rendering, full contact-URI discovery, Piper, tones, and signatures. Module files are staged before activation, the previous module tree is restored if installation fails, and AMI integration is rebuilt and retried automatically before reporting failure.
- Preserved the central `.config` byte-for-byte through the production PBX update and repeated module refreshes. No credentials, generated config, voice models, logs, caches, or signatures are included in the release package.

## 0.0.7-beta

- Fixed fresh-install paging portability. Direct pages now stage call files in Asterisk's same-filesystem spool temporary directory before an atomic move into `outgoing`, use a module-owned per-contact PJSIP auto-answer context with vendor-aware Panasonic, Poly, Mitel, OpenStage, and Sangoma header values instead of FreePBX's generated paging macros, and synchronously verify the visual SIP NOTIFY after the required one-second page-first delay. Announcement delivery is serialized, the sender has a 90-second safety timeout, and partial audio delivery retains the cooldown to prevent an immediate duplicate page.
- Strengthened the release installer so a failed module integration refresh can no longer be hidden by copied runtime files. It now verifies the exact audio and auto-answer dialplan handlers, Asterisk spool access as the `asterisk` account, both managed sound links, all four 8 kHz mono 16-bit default tones, AMI `PJSIPShowContacts` authorization, and live endpoint discovery whenever contacts are registered before reporting success.
- Fixed 0.0.6 upgrades that could copy and sign the Dashboard announcement files without refreshing FreePBX Dashboard's persisted hook index, leaving the SIP NOTIFY announcement panel absent. Install, repair, and maintenance now rebuild and verify the stored hook; the release installer also compares both Dashboard files and renders the panel before reporting success. The installer and maintenance worker reassert `0640 asterisk:asterisk` on the protected central config after FreePBX ownership passes and reject a symlinked config path.
- Made the release installer tolerant of the brief Asterisk reload window after `fwconsole reload`: it now retries and explicitly loads `res_pjsip_notify.so` for up to 20 seconds before reporting a genuine SIP NOTIFY failure.
- Fixed the General Settings manual updater so its cron-launched root worker has the complete system path and can reliably find FreePBX tooling. The update button is now shown only when a strictly newer beta release is available, forged/current-version requests are rejected server-side, and queued updates expose authenticated queued/checking/installing/complete/failed progress. The page displays a spinner while work runs, a green completion checkmark, and then refreshes to the installed version; failures remain visible with an actionable message.
- Added FreePBX Framework 17.0.30 compatibility to the update-safe Mass Notify menu integration. Framework changed its final-menu comparator from `return 1;` to `return true;`; repair, reinstall, maintenance drift detection, and uninstall cleanup now recognize both forms without duplicating or stranding the managed block. This compatibility fix does not install or upgrade Framework or any other FreePBX module.
- Fixed complete uninstall when FreePBX cannot redownload Dashboard or Framework. The standalone and packaged uninstallers now retry against a fresh stable repository cache, restore stock modules before deleting recovery tools, and use a locally verified cleanup signature as an availability-safe fallback. The fallback removes all private signing material, retains only the public verification key, avoids the raw `module.sig status 4` failure, and tells the administrator how to replace the temporary local signature with the vendor copy when repository access returns. The same path can repair a PBX after an earlier interrupted uninstall.
- Reworked the first-run wizard so Weather and Lightning are explicit opt-ins that default to No. Each integration's fields and audio options remain hidden and disabled until selected, disabled integrations retain their saved values, Lightning no longer browser-requires a Weather trigger zone while turned off, and compact checkbox alignment keeps labels beside their controls. Lightning Alerts now carries a Labs badge while Xweather support remains in beta testing.
