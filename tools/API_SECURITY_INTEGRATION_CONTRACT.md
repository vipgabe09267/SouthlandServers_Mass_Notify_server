# Internal implementation contract (R18 / R20)

Canonical helper: `slsmassnotifyserver/api/sls-mass-notify/security.php`, namespace `SLS\MassNotify\ApiSecurity`. Install to `/var/www/html/api/sls-mass-notify/security.php`. Both API entry points require that same file. Module class must require `__DIR__ . '/api/sls-mass-notify/security.php'`. Add file to package/runtime verification and protected ownership inventories.

Additive defaults: `control_api.credentials = []`; top-level `api_network = ['trusted_proxy_cidrs' => []]`. Do not modify saved active configuration merely on reads/install. Preserve both fields in routine UI saves, client config/normalization/import, pending settings, and exports. Config API must reject changes to these fields: only authenticated FreePBX admin GUI manages credentials/proxies. New helpers `ApiSecurity::credentials($rows)` and `::network($object)` validate and normalize strictly, throwing `DomainException`; do not silently drop unknown scopes or malformed rows and grant a broader fallback. Existing `control_api.api_key` remains backward compatible.

Credential row: `{id: api_<24 lower hex>, name: string<=80bytes, secret_hash: sha256hex, scopes: [read|send|test|config], audience: {unrestricted: bool, extensions: [digits], desktop_client_ids: [client_id], announcement_group_ids: [group_id], nws_zone_ids: [zone_id], voice_recipient_ids: [id], webhook_ids: [announcement webhook id]}, created_at: UTC ISO8601, revoked_at: ''|UTC ISO8601}`. Every audience list defaults empty. Empty restricted audience grants no delivery. Configuration permission requires unrestricted audience. Group permission includes its current recipients; explicit desktop permission binds stable client_id, not username. Named credential max100, listmax1000. `ApiSecurity::issue($input)` returns `['credential' => stored row, 'secret' => one-time secret]`; never store/redisplay secret. `::revoke($rows,$id)` idempotently stamps existing row, unknown ID errors. Show safe metadata minus secret_hash in GUI/API; redact secret_hash for exported redacted config.

GUI creation and revocation should persist immediately under configuration lock with active+pending credential list consistency, preserving unrelated pending changes. Revoke must remain effective after later Apply Config. A failed write must not display success/secret as usable. API network edits may use existing explicit Submit/Apply workflow. UI must warn that proxy CIDRs only work with a proxy overwriting X-Forwarded-For/X-Forwarded-Proto, and require exact hosts/narrow networks (max32, IPv4/IPv6, no /0). Forwarded host is never trusted. Do not auto-detect proxies.

Add `credential_id` string (`legacy`, `api_<24hex>`, or empty unauthenticated) to audit storage's accepted record shape; old records without it remain accepted. Index adds this field after auth; never logs secret/hash.

Endpoint policy: read scope permits aggregate status. Global events/config require unrestricted read (config resource additionally config scope). Restricted delivery reads/retries require same issuing credential ID on job, enforced inside AnnouncementDelivery. Send requires send scope; test requires test scope plus explicit permitted NWS zone IDs (never implicit all for restricted keys). Config requires unrestricted config scope and cannot manage API credential/proxy trust settings. Future unknown scope/channel defaults deny.

AnnouncementDelivery hooks are owned by api_permissions agent: exact resolved audience authorization before queuing, safe credential attribution, job ownership read/retry guards, current credential/revocation/audience recheck before worker delivery, intersection of frozen recipients with currently permitted recipients (no newly authorized additions). No mainclass signature changes required; endpoint sets trusted `sls_control_principal` global only after authentication. Module's current `controlApiSendAnnouncement` forces trigger_source Control API, and the trait reads that trusted global. NWS test additionally needs mainclass pre-trigger recheck helper call against its current settings snapshot if config can change between endpoint auth and trigger.
